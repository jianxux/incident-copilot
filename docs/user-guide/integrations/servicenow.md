# 🔧 ServiceNow Integration

Integrate Incident Copilot with ServiceNow to automatically create and update incident records, sync resolution data, and leverage your ITSM workflow.

---

## 📋 Prerequisites

- [ ] ServiceNow instance (Rome or later recommended)
- [ ] Admin or Integration Admin role
- [ ] OAuth application or API credentials
- [ ] Incident Copilot running and accessible

---

## 🔧 Step-by-Step Setup

### Step 1: Create a ServiceNow Integration User

1. Log in to ServiceNow as an admin
2. Navigate to **User Administration** → **Users**
3. Click **New**
4. Configure:
   - **User ID:** `incident_copilot`
   - **First Name:** `Incident`
   - **Last Name:** `Copilot`
   - **Active:** ✅ Checked
   - **Web service access only:** ✅ Checked
5. Click **Submit**
6. Grant roles:
   - `itil` (for incident management)
   - `rest_api_explorer` (for API access)

### Step 2: Create OAuth Application (Recommended)

1. Navigate to **System OAuth** → **Application Registry**
2. Click **New** → **Create an OAuth API endpoint for external clients**
3. Configure:
   - **Name:** `Incident Copilot`
   - **Client ID:** Auto-generated (copy this)
   - **Client Secret:** Generate and copy
   - **Redirect URL:** `https://your-domain.com/oauth/callback`
4. Click **Submit**

### Step 3: Configure in Incident Copilot

Add to your `.env`:

```bash
# ServiceNow Configuration
SERVICENOW_INSTANCE=your-instance.service-now.com
SERVICENOW_CLIENT_ID=your-oauth-client-id
SERVICENOW_CLIENT_SECRET=your-oauth-client-secret
SERVICENOW_USERNAME=incident_copilot
SERVICENOW_PASSWORD=your-password

# Optional: Assignment groups and categories
SERVICENOW_DEFAULT_ASSIGNMENT_GROUP=IT Support
SERVICENOW_DEFAULT_CATEGORY=Software
```

### Step 4: Restart Incident Copilot

```bash
docker-compose restart
```

## 🔄 Sync Features

### Automatic Incident Creation

When an incident triggers in PagerDuty/Opsgenie, Incident Copilot can automatically create a matching ServiceNow incident:

```json
{
  "short_description": "payments-api: High Error Rate",
  "description": "Alert triggered with AI-generated context...",
  "urgency": 1,
  "impact": 2,
  "category": "Software",
  "assignment_group": "Platform Engineering",
  "caller_id": "incident_copilot",
  "work_notes": "Context card generated by Incident Copilot..."
}
```

### Resolution Sync

When incidents are resolved, Incident Copilot updates ServiceNow:

- Sets state to **Resolved**
- Adds resolution notes
- Records resolution time
- Links postmortem document if available

### Bidirectional Sync (Optional)

Enable bidirectional sync to update PagerDuty/Opsgenie when ServiceNow incidents change:

```bash
SERVICENOW_BIDIRECTIONAL_SYNC=true
SERVICENOW_WEBHOOK_SECRET=your-webhook-secret
```

## 🔑 Environment Variables

| Variable | Required | Description |
|----------|----------|-------------|
| `SERVICENOW_INSTANCE` | ✅ | ServiceNow instance URL (without https://) |
| `SERVICENOW_CLIENT_ID` | ✅* | OAuth client ID |
| `SERVICENOW_CLIENT_SECRET` | ✅* | OAuth client secret |
| `SERVICENOW_USERNAME` | ✅ | Integration user username |
| `SERVICENOW_PASSWORD` | ✅** | Integration user password |
| `SERVICENOW_DEFAULT_ASSIGNMENT_GROUP` | ❌ | Default assignment group |
| `SERVICENOW_DEFAULT_CATEGORY` | ❌ | Default incident category |
| `SERVICENOW_BIDIRECTIONAL_SYNC` | ❌ | Enable two-way sync (default: false) |

*Required for OAuth authentication
**Required for basic authentication (if not using OAuth)

## 📊 Field Mapping

### Severity Mapping

| PagerDuty/Opsgenie | ServiceNow Impact | ServiceNow Urgency |
|--------------------|-------------------|--------------------|
| Critical (P1) | 1 - High | 1 - High |
| High (P2) | 2 - Medium | 1 - High |
| Medium (P3) | 2 - Medium | 2 - Medium |
| Low (P4) | 3 - Low | 3 - Low |

### Custom Field Mapping

Configure custom field mappings:

```bash
SERVICENOW_FIELD_MAP='{
  "alert_service": "u_affected_service",
  "alert_url": "u_alert_link",
  "context_card_url": "u_context_url"
}'
```

## ✅ Testing the Integration

### Verify API Access

```bash

curl -X GET "https://YOUR-INSTANCE.service-now.com/api/now/table/sys_user?sysparm_limit=1" \
  -H "Accept: application/json" \
  -u "incident_copilot:password"
```


## 🐛 Troubleshooting

### Authentication Errors

**Symptoms:**
- HTTP 401 responses
- "User not authorized"

**Solutions:**
1. Verify username/password
2. Check user is active
3. Ensure web service access is enabled
4. Verify OAuth tokens haven't expired

### Incident Not Created

**Symptoms:**
- Webhook received but no ServiceNow incident

**Checks:**
1. Verify ServiceNow integration is enabled
2. Check assignment group exists
3. Review logs for creation errors
4. Ensure required fields are populated

### Field Mapping Errors

**Symptoms:**
- "Invalid field" errors
- Missing data in ServiceNow

**Solutions:**
1. Verify custom field names (case-sensitive)
2. Check field is accessible to integration user
3. Ensure field type matches (string, integer, etc.)
