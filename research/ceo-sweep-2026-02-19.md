## Task 1: Bug Fix — Connection Test Crash

### Root Cause
When testing an integration (e.g., PagerDuty) via the onboarding wizard, if the PagerDuty API returned a non-200, non-401 HTTP status code, the `test_integration` endpoint in `src/web/routes.py` had no return statement for that code path. Python implicitly returned `None`, which FastAPI serialized as JSON `null`. The frontend JavaScript at `onboarding_wizard.html:233` then crashed with `Cannot read properties of null (reading 'details')` when accessing `res.details`.

### Fix Applied
1. **Backend (`src/web/routes.py`):** Added a fallback `return {"ok": False, "details": f"PagerDuty API returned {resp.status_code}"}` after the 401-handling block, so all PagerDuty response codes produce a valid JSON response.
2. **Frontend (`src/web/templates/onboarding_wizard.html`):** Made the `setVerify` call null-safe: `setVerify(name, res && res.ok, res ? (res.details || 'Connection verified') : 'No response from server')`.
